# 最近常听去重设计

## 目标

首页“最近常听”中，同一首音乐只展示一次，同时保持现有的最近播放顺序。

## 曲目身份

使用 `Track.source` 与 `Track.id` 的组合作为唯一身份。只有两个字段都相同才视为同一首音乐；不同音源下的同名曲目不会合并。

## 方案

`PlaybackHistoryRepository` 继续返回完整播放历史，保留其事件记录语义。`HomeController` 在把播放历史映射到 `HomeState.continueListening` 时按 `source + id` 去重，并保留每个身份第一次出现的记录。由于服务端历史沿用当前顺序，这会保留每首歌曲最近一次出现的位置。

不修改首页组件、服务端接口或播放历史仓库。这样 `HomeState.continueListening` 与首页实际展示一致，其他可能需要完整历史的消费者不受影响。

## 验证

在 `test/features/home/home_controller_test.dart` 增加控制器测试：播放历史包含重复的 `source + id` 时，状态仅保留第一次出现的曲目，并维持不同曲目的原顺序。先运行新增测试确认其因缺少去重而失败，再实现最小改动并重新运行相关测试。

## 边界与风险

- 同名但 `source` 或 `id` 不同的曲目仍分别展示。
- 同一 `source + id` 的后续历史项即使携带不同元数据，也不会替换首次出现的记录。
- 假设服务端返回顺序仍代表当前首页采用的最近播放顺序；本次不改变或重排该顺序。
