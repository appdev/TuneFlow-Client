# TuneFlow 桌面播放器 Vinyl Portal 设计

日期：2026-08-14

状态：待用户复核书面规格

## 决策背景

当前桌面播放器将一张约 `52vw` 的黑胶向窗口左侧移出约自身直径的
25%。唱片虽然具有冲击力，但裁切仅由窗口边界产生，容易被理解为页面
没有展示完整，而不是刻意构图。

用户不接受“缩小并完整显示唱片”的普通方案，希望保留大胆、具有品牌
辨识度的播放器舞台。经过完整悬浮、轻微出血、封套滑出、真实唱盘、
声轨轨道和唱片切片等方向比较，最终选择 D「Vinyl Portal」。

本设计取代上一版《桌面播放页唱片与置顶标题设计》中“唱片直接越过窗口
左边界并隐藏约 25%”的视觉规则。上一版关于歌词、标题、背景、底部控制、
播放状态和移动端边界的其他约束继续有效。

## 目标

- 保留大尺寸旋转黑胶的沉浸感和视觉冲击力。
- 让裁切发生在一个明确设计的舷窗容器内，使其成为可理解的视觉语言。
- 完整展示唱片中心封面和轴孔，只裁切外围沟槽。
- 用一条克制的播放轴线把视觉装饰与真实播放进度联系起来。
- 保持右侧歌曲信息、歌词和底部播放控制的既有层级与功能。
- 在 1024×768 和 1440×960 桌面窗口中无溢出、无遮挡、无不可达控制。

## 非目标

- 不改动移动播放器、Mini Player、播放协议、歌词解析或队列逻辑。
- 不增加真实唱臂、唱盘机身、3D 透视或高成本粒子效果。
- 不把播放轴线做成第二个可拖动进度条。
- 不复制 Apple Music、Plexamp、Roon 或其他播放器的具体像素和品牌元素。
- 不修改背景生成、底部进度条、核心播放按钮、音质或队列的交互。

## 最终视觉结构

桌面播放器继续采用 Split Studio：左侧为主视觉舞台，右侧为固定歌曲信息
与滚动歌词，底部为现有播放控制。

左侧新增 `Vinyl Portal` 舷窗：

- 舷窗外形为左侧大圆弧、右侧垂直切面的非对称容器。
- 容器使用现有播放器语义色构成低对比边界与轻微内阴影，不增加玻璃卡片。
- 黑胶尺寸大于舷窗本身，外围沟槽由舷窗边界裁切。
- 中心封面、轴孔和足以辨认旋转的内圈始终完整可见。
- 唱片中心留在舷窗可见区域内，不再依赖窗口边缘解释裁切。
- 舷窗与右侧歌词列保持清晰间隔，不跨越或遮挡歌词。

舷窗右侧放置一条细薄的垂直播放轴线：

- 使用现有 `accent` 颜色，避免新增页面私有色。
- 显示克制的 `NOW PLAYING` 标识。
- 轴线上有一个只读进度标记，位置由 `position / duration` 映射。
- 轴线和标记不进入焦点顺序，也不替代底部可操作进度条。
- 屏幕阅读器继续只读取现有进度控制，装饰轴线设为无语义。

## 数据与状态

`DesktopPlayerStage` 从现有 `PlayerState` 读取：

- 当前歌曲封面、标题和语义标签；
- `playing` 与 `processing`，用于控制黑胶旋转；
- `position` 与 `duration`，用于计算轴线进度标记；
- 减少动态效果策略，用于关闭持续旋转和进度标记过渡。

进度比值按 `0...1` 限制。持续时间为空、为零或无效时，标记停在轴线起点，
底部既有进度行为不变。封面缺失或加载失败时继续使用项目统一的确定性默认
封面；舷窗布局不改变。

## 动画

- 仅当 `playing == true` 且 `processing == PlayerProcessing.ready` 时旋转。
- 暂停、缓冲、完成和错误时停在当前角度，恢复后从原角度继续。
- 唱片继续使用现有匀速旋转周期，不因舷窗设计改变播放语义。
- 进度标记仅用 `transform` 沿轴线移动，不动画布局属性。
- 减少动态效果开启时禁用唱片旋转；进度标记直接跳到目标位置。
- 黑胶保持在 `RepaintBoundary` 内，轴线进度更新不得触发歌词和背景重绘。

## 响应式规则

- 1440×960：舷窗作为左侧主视觉，占用左侧舞台的大部分高度，但不得进入
  底部控制安全区。
- 1024×768：按可用高度和左侧列宽共同缩放舷窗；中心封面保持完整，右侧
  垂直切面和播放轴线仍可辨认。
- 更低的桌面窗口优先缩小舷窗和唱片，不移动或压缩底部核心控制。
- 当桌面宽度不足以保持歌词安全间隔时，缩小唱片外围裁切量，不允许覆盖
  歌词列。
- 移动断点继续使用现有移动唱片页面，不构建桌面舷窗和轴线。

## 组件边界

- `DesktopPlayerStage` 负责舷窗在桌面双栏中的尺寸和位置。
- 新增 `DesktopVinylPortal`，负责容器裁切、轴线和进度标记。
- `VinylRecord` 继续负责唱片绘制、封面、语义和旋转生命周期。
- `PlayerController` 与音频实现不变；本设计只消费已有状态。
- `LyricsView` 不因舷窗设计增加行为或数据依赖。

预计生产修改范围：

- `lib/features/player/desktop_player_stage.dart`
- `lib/features/player/desktop_vinyl_record.dart`
- 新增 `lib/features/player/desktop_vinyl_portal.dart`

测试和桌面播放器视觉基线可同步更新。背景、底部控制、移动播放器和业务
控制器不在修改范围内。若实现发现必须修改这些边界，需先重新确认设计。

## 错误与可访问性

- 默认封面、封面加载错误和歌曲切换沿用 `AppArtwork` 的现有回退路径。
- 歌词为空或错误不隐藏舷窗、歌曲信息和播放控制。
- 舷窗边框、沟槽和播放轴线均为装饰，不重复封面或进度语义。
- 唱片整体继续提供“歌曲名 + 封面”语义标签。
- 颜色不是播放状态的唯一提示；底部播放按钮和既有语义仍是权威状态。
- 亮色与暗色主题都使用现有 Mist Sea 令牌，并满足必要的边界对比度。

## 验证

Widget 测试覆盖：

- 桌面播放器存在 Vinyl Portal，而不是唱片直接由窗口边界裁切。
- 1440×960 和 1024×768 下舷窗、唱片、歌词列和底部控制无重叠或溢出。
- 中心封面和轴孔完全落在舷窗可见范围内，外围沟槽被明确裁切。
- 播放 Ready 时旋转；暂停、缓冲和减少动态效果时停止且不复位。
- `position / duration` 正确映射到轴线进度，并对零时长和越界值进行限制。
- 轴线不进入语义树，现有进度条仍是唯一可操作进度控制。
- 默认封面与加载错误保持舷窗几何不变。
- 移动播放器相关测试继续通过且输出不变。

视觉验证覆盖：

- 亮色和暗色的 1024×768、1440×960 桌面播放器快照。
- 使用真实封面检查中心裁切、背景关系和歌词安全间隔。
- 固定时间推进检查旋转、暂停续转和轴线标记位置。
- 对比修改前后，确认背景、右侧歌词结构和底部控制没有非预期变化。

## 风险与控制

- 大唱片与非矩形裁切可能增加合成成本：使用明确裁切边界并隔离重绘。
- 轴线可能与底部进度形成重复：保持只读、弱层级，不显示第二组完整时间。
- 1024px 宽度下左侧视觉可能挤压歌词：按可用宽高联合缩放，而不是固定 `vw`。
- 亮色主题下黑胶边缘可能过重：只调整语义令牌派生的边界和阴影，不引入
  页面私有颜色。
- 当前工作区包含用户未提交修改：实施只做播放器相关局部补丁，不清理或
  覆盖无关变更。
