# 歌曲操作弹层重设计

## 目标

重设计移动端共享歌曲操作弹层，解决当前弹层高度过大、内部空白过多、歌曲信息与操作层级不清的问题。播放器、搜索、发现、专辑等入口统一复用同一套可扩展组件；本次不改变任何操作的业务语义。

## 视觉结构

弹层采用已确认的“快捷操作 + 次级列表”结构：

1. 顶部保留简短拖拽柄与关闭入口。
2. 歌曲摘要区展示 44–48 dp 封面、单行歌曲名、单行歌手名，以及可用时的音质标签。封面缺失时沿用现有默认歌曲封面。
3. 快捷操作区使用参考图式的图标卡片：图标位于独立圆角方块内，文字置于下方，整项为不小于 48 dp 的触控目标。
4. 次级操作区使用全宽列表行，左侧图标、中央标题、右侧导航提示；列表与快捷区通过留白或细分隔线区分。
5. 移除现有弹层内部的大面积嵌套玻璃卡片，避免“弹层里再套一个空白面板”。

弹层按内容自适应高度，最高不超过可用屏幕高度的 72%。内容超过上限时，歌曲摘要与快捷区保持可见，仅次级列表滚动。

## 操作分级

现有六项操作分为：

- 快捷操作：立即播放、下一首播放、添加到歌单、下载。
- 次级操作：添加到播放队列、查看歌词。

播放器当前只提供“添加到歌单”和“下载”，两项都进入快捷区并保持左对齐，不拉伸成超宽按钮。

快捷区最多展示四项。后续新增功能默认进入次级列表；只有明确属于高频、可立即执行且适合短标签的操作，才标记为快捷操作。若快捷操作超过四项，超出的项目按原顺序自动进入次级列表，避免破坏布局。

## 组件与接口

- `TrackAction` 增加展示优先级，区分快捷操作和次级操作；默认值为次级，保证未来新增功能安全降级。
- `buildTrackActions` 为现有六项操作写入上述优先级，不改变 `invoke`、禁用状态或错误原因。
- 播放器自行构造的“添加到歌单”和“下载”动作必须显式标记为快捷操作。
- `TrackActionSheet` 负责歌曲摘要、快捷操作和次级列表的布局，并继续使用 `track-action-<id>` 稳定键与现有语义。
- `showMobileTrackActions` 使用歌曲操作专属的紧凑 Sheet 配置，允许传入歌曲摘要标题区域并关闭通用的移动端内层玻璃包裹。
- 通用 `showAppSheet` 的默认外观和其他调用方保持不变；若需要扩展其参数，新增参数必须有保持现状的默认值。
- 桌面 `DesktopTrackActionsButton` 和右键菜单继续使用单列菜单，不套用移动端卡片布局。

## 数据与交互

- 歌曲摘要始终来自当前传入的 `Track` 与 `SearchTrackMetadata`，不发起额外网络请求。
- 点击快捷卡片或次级列表行继续执行对应 `TrackAction.invoke`。
- 需要打开下一层弹层的操作必须先完成当前弹层的关闭动画，再打开目标弹层，避免路由重叠。
- 禁用操作保留在原位置，使用现有禁用原因替代标题并呈现不可点击状态。
- 点击遮罩、关闭按钮或下滑关闭时不执行任何操作。

## 可访问性与响应式

- 每个操作提供完整语义标签，不能只依赖图标表达含义。
- 操作触控区域最小 48 × 48 dp；快捷卡片文字最多两行，超长文字省略。
- 320 dp 宽度下快捷区仍保持单行四项；通过缩小卡片间距和图标容器而不是缩小触控目标适配。
- 文字缩放时允许快捷区换行；次级列表继续保持全宽，弹层通过列表滚动控制总高度。
- 浅色、深色和动态播放器主题均使用现有 `AppTokens`，不写死参考图中的颜色。

## 图标规范

- 操作图标继续以 `TrackAction.icon` 为唯一数据源；移动端快捷卡片、次级列表、桌面弹出菜单和右键菜单不得为同一操作各自替换图标。
- 普通操作统一使用项目已采用的 `LucideIcons`。禁止从其他图标库临时挑选近似图标，也不使用 Emoji、自绘字符或新增 SVG 来模仿参考图。
- 播放、暂停以及标准媒体传输图形继续使用集中定义的 `AppPlaybackIcons` / `AppPlaybackGlyph`；不得重新引入原始 `LucideIcons.play`、`LucideIcons.pause` 或页面局部播放图形。
- 本次沿用现有语义映射：立即播放使用 `AppPlaybackIcons.play`，下一首播放使用 `LucideIcons.listStart`，添加到播放队列使用 `LucideIcons.listPlus`，查看歌词使用 `LucideIcons.messageSquareText`，添加到歌单使用 `LucideIcons.heartPlus`，下载使用 `LucideIcons.download`。
- 快捷卡片图标建议为 22 dp，次级列表图标为 18–20 dp，关闭与导航提示遵循现有 20 dp 体系；只调整图标容器尺寸，不拉伸或改变图标笔画。
- 图标颜色继承 `AppTokens`：普通可用操作使用语义强调色，禁用操作使用 muted 色；未来若增加破坏性操作，只能使用现有 danger token，不能写死颜色。
- 新增 `TrackAction` 时必须优先复用语义最接近的现有 Lucide 图标，并在动作模型中一次性定义；若没有合适图标，应先扩展集中式语义图标定义，再供所有入口复用。

## 错误与边界

- 操作失败继续使用各页面现有错误反馈，不在展示组件中吞掉异常或新增业务提示。
- 无封面、无歌手、无音质标签时摘要区收紧，不保留空占位。
- 没有次级操作时不渲染次级区或分隔线；没有快捷操作时次级列表直接承接摘要区。
- 操作数量超过可视上限时只滚动次级列表，不允许整个弹层撑出屏幕。

## 验证

- Widget 测试覆盖播放器两项快捷操作、搜索六项混合分组，以及快捷项超过四项后的自动降级。
- 测试确认歌曲摘要展示标题、歌手、音质和封面回退。
- 测试确认禁用项、无次级项、320 dp 宽度和大字体下无溢出。
- 测试确认六项现有操作继续使用统一图标映射，移动端与桌面消费同一个 `TrackAction.icon`，并检查生产代码未重新出现原始 Lucide 播放/暂停图标。
- 保留并运行现有操作调用、歌单选择、下载、失败保护和播放队列回归测试。
- 运行相关文件格式化、定向静态分析与歌曲操作/播放器聚焦测试。
