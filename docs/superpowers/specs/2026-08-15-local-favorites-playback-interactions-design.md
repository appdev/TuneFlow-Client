# 本地音乐收藏与播放交互一致性设计

## 目标

在不改变 Service API 和现有音乐数据边界的前提下，完成四项相互关联的体验改进：

1. 本地音乐能够复用现有“收藏到歌单”流程。
2. 带填充背景的主要播放/暂停按钮统一使用实心图形和白色前景。
3. 全应用取消扩散式点击水波纹，同时保留必要的交互状态反馈。
4. 提高浅色模式播放进度条底轨的可见性，并验证应用可跟随系统深浅主题切换。

## 已确认的产品行为

- 本地歌曲点击收藏后，显示现有歌单选择器，可选择“我的收藏”或其他 Service 歌单。
- 收藏仍调用现有 `PlaylistRepository.addTracks`；不新增客户端收藏数据库，也不创建特殊本地收藏格式。
- 首页、详情页、搜索结果、迷你播放器和完整播放器中，带填充背景的主要播放/暂停按钮使用实心播放或暂停图形。
- 填充式播放按钮使用白色图标；带文字的按钮同时使用白色文字，并保证背景与白色前景达到可读对比。
- 普通列表、菜单、上一首、下一首以及没有填充背景的操作图标不强制改白色。
- 所有 Material/Ink 点击控件取消向外扩散的水波纹；悬停、平面按下态、键盘焦点、禁用和加载反馈继续保留。
- 浅色模式的播放进度底轨必须清晰可辨；进度条的交互高度和视觉高度保持不变。
- 主题默认“跟随系统”，用户手动选择浅色或深色后固定使用所选主题。

## 方案与边界

### 本地音乐收藏

`LocalLibraryScreen` 注入现有 `PlaylistRepository`。桌面歌曲行恢复收藏列，移动歌曲行增加独立的收藏按钮。点击收藏按钮不得触发行播放。

收藏流程与搜索页保持一致：

1. 调用 `PlaylistRepository.list()` 读取包含内置歌单的列表。
2. 使用现有应用 Sheet 展示“添加到歌单”。
3. 选择目标后调用 `addTracks(playlist.id, [track])`。
4. 成功显示“已添加到 …”，失败保留当前页面并显示错误反馈。

本地 `Track` 使用 `LibraryTrack.musicInfo` 已解析出的完整快照原样提交，不以 `LibraryTrack.id` 替换歌曲 ID，不改变本地曲库的只读属性。

本次只在本地音乐页面接入现有流程，不迁移搜索、发现和在线歌单中已有的重复选择器实现，避免扩大回归面。后续若需要统一选择器，可单独抽取共享组件。

### 实心播放图形与白色前景

新增语义化的实心播放/暂停图形组件，避免在各页面继续直接选择线框 `LucideIcons.play`。组件能够继承 `IconTheme`，并明确支持播放与暂停两种状态。

新增播放操作语义颜色，而不是继续在页面内混用 `tokens.background`、`primaryForeground`、Material 默认前景和硬编码 `Colors.white`：

- `playbackAction`：填充式主要播放按钮背景。
- `playbackActionForeground`：固定为纯白色前景，由主题令牌提供，页面不得硬编码。

浅色和深色主题分别提供可访问的 `playbackAction`。背景需要与白色文字达到至少 `4.5:1`，图形达到至少 `3:1`。这组令牌只影响播放操作，不改变连接、保存、确认等其他主要按钮。

覆盖范围：

- 首页桌面“继续播放”和移动端“继续收听”。
- 本地音乐、普通歌单和在线歌单的“播放全部”。
- 搜索结果中的填充式播放按钮。
- 移动与桌面完整播放器的中心播放/暂停按钮。
- 移动与桌面迷你播放器中带填充背景的主播放/暂停按钮。

普通菜单和无填充列表中的播放动作仍可使用现有中性色，但若它们呈现播放三角形，应使用同一实心图形以保持图形语义一致。

### 取消点击水波纹

在应用 Material 主题层设置 `NoSplash.splashFactory`，统一取消 `InkWell`、`IconButton` 及 Material 按钮的扩散式 splash。不要逐一替换为 `GestureDetector`，也不要为每个控件重复设置透明 overlay。

取消水波纹不等于取消交互反馈：

- 鼠标悬停继续使用现有颜色或表面变化。
- 指针按下保留平面的 highlight/pressed 状态，不产生径向扩散。
- `focus-visible` 焦点环立即出现，不参与动画。
- disabled、loading、error 和 success 状态沿用组件现有语义。
- 语义、键盘激活、触控目标和长按行为不得因去除水波纹而改变。

自绘黑胶高光中的 `highlightColor` 属于画面纹理，不是点击水波纹，不在移除范围内。

### 播放进度条对比度

当前 `PlaybackProgress` 默认使用 `surfaceWarm` 作为非活动轨道；浅色主题中为 `#EAEAEA`，与 `#F6F6F6` 页面背景过于接近。桌面动态播放器还覆盖为前景色 16% 透明度，同样偏弱。

主题增加 `playbackTrackInactive` 语义色：

- 浅色主题与常见背景之间达到至少 `3:1` 的可见对比。
- 深色主题保持明显但弱于活动轨道。
- 活动轨道继续使用 `accent` 或当前封面提取的 `vinylAccent`。
- 时间标签、轨道高度、滑块尺寸、点击范围和拖动行为不改变。

桌面动态播放器通过统一的对比度辅助函数生成底轨：以 `palette.foreground` 为候选，从 32% 开始逐级提高不透明度，分别与 `palette.backgroundBase` 和 `palette.backgroundCompanion` 合成并检查对比度；两组均达到 `3:1` 后使用该结果，仍不满足时回退为不透明 `palette.foreground`。不得继续使用固定且未经验证的 16% 透明度。测试覆盖代表性浅色与深色调色板。

### 跟随系统主题

现有设置链路保留：

- `AppSettings.themeMode` 默认 `ThemeMode.system`。
- Shared Preferences 保存 `system`、`light` 或 `dark`。
- `ShadApp.custom` 同时接收 `theme`、`darkTheme` 和当前 `themeMode`。
- 内层 `MaterialApp.router` 使用外层当前 Material 主题，使 Shad 与 Material 控件保持同一亮度。

当宿主平台通过 Flutter `platformBrightness` 上报亮度变化时，`ThemeMode.system` 应实时切换；手动 `ThemeMode.light` 或 `ThemeMode.dark` 不响应系统变化。未发现 Android、iOS、macOS、Windows 或 Linux 工程中的强制固定外观配置。

Flutter 官方约束是：不支持系统亮度概念的平台可能始终报告 `Brightness.light`。因此验收分为共享框架行为与设备运行时行为，不能用 Widget 测试冒充所有平台真机证据。

## 错误与状态处理

- 读取歌单失败：关闭选择流程并显示可理解的错误，不改变本地音乐列表。
- 添加歌曲失败：不显示成功消息，不关闭或重建本地曲库数据。
- 歌单列表为空：显示现有“还没有歌单”空状态。
- 重复收藏：沿用 Service 当前行为，不在客户端推断或去重。
- 主题设置读取失败或尚未完成：继续采用 `ThemeMode.system` 的安全默认值。
- 系统不提供亮度偏好：按 Flutter 行为使用浅色主题，用户仍可手动选择深色。

## 测试与验收

### 本地收藏

- 桌面和移动本地歌曲均显示收藏入口。
- 点击收藏入口不会触发播放。
- 选择“我的收藏”和普通歌单时提交正确歌单 ID 与完整本地 `Track`。
- 成功和失败反馈正确；空歌单显示空状态。

### 播放按钮

- 主要填充播放按钮使用实心播放/暂停图形。
- 浅色和深色主题下前景为白色，背景/前景对比满足约束。
- 页面不再各自硬编码播放按钮前景色。
- 普通中性操作按钮不被错误改成白色。

### 无水波纹

- 应用主题的 splash factory 为 `NoSplash.splashFactory`。
- 代表性的卡片、`InkWell`、`IconButton` 和主按钮点击不创建扩散 splash。
- 点击、键盘激活、焦点、hover、disabled 和 loading 行为保持有效。

### 进度条

- 浅色模式默认非活动轨道与背景达到至少 `3:1`。
- 深色模式及动态播放器底轨清晰且弱于活动轨道。
- 拖动、点击跳转、无时长禁用和扩大交互区域测试继续通过。

### 系统主题

- Widget 测试模拟宿主从浅色切换到深色，确认 Shad 与 Material 两层亮度及令牌同时变化。
- `ThemeMode.light` 与 `ThemeMode.dark` 在同样模拟下保持固定。
- 设置持久化继续覆盖 `system`、`light` 和 `dark`。
- 有可用设备时，分别验证 Android/iOS、Windows/macOS/Linux 的运行时切换；无设备的平台在交付中明确标为未真机验证。

## 非目标

- 不修改 Service API、歌单数据格式或本地曲库扫描机制。
- 不实现收藏状态查询、心形已收藏态或客户端重复检测。
- 不重做所有按钮组件或页面布局。
- 不删除 hover、focus、pressed、disabled 或 loading 状态。
- 不改变播放器进度计算、音频状态或 seek 数据流。
- 不承诺宿主平台本身不支持的系统亮度能力。

## 风险与约束

- 当前工作树包含大量用户未提交修改，实施必须使用窄范围补丁并避免覆盖相邻工作。
- `design.md` 是锁定的应用设计系统；新增播放语义令牌和无水波纹交互规则需要同步记录，避免代码与设计文档分叉。
- 白色前景不能直接套用当前深色主题的高亮荧光绿；必须使用经过对比验证的播放专用背景。
- 全局取消 splash 会影响所有 Material/Ink 控件，必须用代表性跨页面测试确认交互语义和状态反馈仍然存在。
- 当前没有连接 Android 设备；设计阶段只有代码与自动化证据，没有真机主题切换证据。
