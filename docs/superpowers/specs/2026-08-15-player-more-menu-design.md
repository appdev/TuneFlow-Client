# 播放器更多菜单设计

## 目标

消除移动端播放器右上角省略号按钮与底部播放队列按钮的重复功能。底部列表按钮继续作为播放队列的唯一直接入口；右上角省略号改为当前歌曲的更多操作入口。

## 交互设计

- 点击右上角省略号后，使用项目现有的移动端底部操作菜单样式。
- 菜单标题展示当前歌曲标题，并仅提供“添加到歌单”和“下载”两项。
- “添加到歌单”打开现有歌单选择界面；选择歌单并成功添加后显示成功反馈。
- “下载”按当前歌曲元数据推导出的音质加入下载队列；成功或失败均使用项目现有消息反馈。
- 底部播放队列按钮及其行为保持不变。

## 组件与数据流

- 播放器路由为 `PlayerScreen` 提供 `PlaylistRepository` 与 `DownloadRepository`，不在播放器内部创建连接或服务依赖。
- `PlayerScreen` 根据当前 `Track` 构造两项 `TrackAction`，复用现有 `showMobileTrackActions`、`TrackActionSheet` 与 `SearchTrackMetadata`。
- 顶部按钮回调从 `onQueue` 分离为 `onMore`，语义标签从“播放队列”改为“更多操作”。
- 添加歌单与下载操作沿用现有仓库接口和统一错误文案，不改变播放状态、队列或当前视图。

## 错误与边界

- 没有歌单时显示现有空状态，不创建隐式歌单。
- 仓库请求失败时保留播放器页面和当前播放状态，并显示操作失败反馈。
- 当前歌曲变化后再次打开菜单，应读取最新歌曲，不能保留旧歌曲引用。
- 本次仅改变移动端播放器顶部入口；桌面播放器与其他歌曲操作菜单不在范围内。

## 验证

- Widget 测试确认顶部省略号的语义为“更多操作”，点击后出现且仅出现“添加到歌单”和“下载”。
- Widget 测试确认底部播放队列按钮仍能打开队列。
- 测试添加歌单和下载分别调用对应仓库，并覆盖成功反馈；至少覆盖一个失败反馈路径。
- 对相关 Dart 文件运行格式化与静态分析，并运行播放器聚焦测试。
