# 冷启动 Service 连接状态界面

## 目标

当应用已保存 Service 地址时，冷启动自动恢复连接期间展示明确的“正在连接”界面；连接失败后返回连接表单，并将之前保存的地址回填到输入框中。首次启动没有历史地址时，继续直接展示空白连接表单。

## 状态与界面

连接入口继续使用现有 `/connect` 路由，由连接页内部根据连接状态和持久化设置选择内容，不新增路由或全局连接状态类型。

### 冷启动自动连接

同时满足以下条件时显示专用连接中界面：

- 本地设置中存在已保存的 Service 地址；
- `connectionProvider` 正在执行冷启动自动连接；
- 用户尚未在当前连接表单中输入新地址。

连接中界面沿用现有连接页的品牌和布局语言，包含：

- TuneFlow 品牌 Logo；
- “正在连接音流服务”标题；
- 当前正在连接的已保存 Service 地址；
- 持续加载动画。

界面不提供取消、重试或进入手动配置的入口。连接成功后由现有路由逻辑进入主页。

### 自动连接失败

自动连接失败后切换为现有连接表单：

- Service 地址输入框回填之前保存的地址；
- 保留并显示现有连接错误提示；
- 用户可以直接重试，也可以修改地址后重新连接；
- 历史地址只用于初始化空输入框，不覆盖用户已经输入或修改的内容。

### 首次启动与手动连接

- 本地没有历史地址时直接显示现有空白连接表单，不显示专用连接中界面。
- 输入框继续显示当前平台对应的示例地址占位符。
- 用户从表单发起连接时，继续在表单内显示按钮加载状态，不切换到冷启动连接中界面。
- 地址仍然只在连接健康检查和 API 版本检查成功后保存；主动断开连接仍然清除地址。

## 实现边界

- 在 `ConnectionScreen` 内增加冷启动连接中视图和一次性历史地址回填逻辑。
- 从现有 `appSettingsProvider` 读取持久化地址，不增加重复存储。
- 继续使用现有 `connectionProvider`、`ConnectionRepository` 和 `/connect` 路由。
- 为新标题增加中英文本地化文案。
- 不增加取消请求、自动重试、退避策略、新路由、依赖或连接状态模型重构。
- 保留工作树中与本功能无关的已有改动。

## 验证

自动化测试应覆盖：

- 存在历史地址且自动连接未完成时，显示连接中界面、品牌 Logo、加载动画和该地址，不显示连接表单。
- 自动连接成功后进入主页。
- 自动连接失败后显示连接表单、错误提示，并将历史地址回填到输入框。
- 没有历史地址时直接显示空白连接表单及平台占位符。
- 用户手动输入或修改的地址不会被异步读取到的历史地址覆盖。
- 手动连接期间保留当前表单与按钮加载反馈。

运行连接页组件测试、连接控制器测试以及相关应用路由测试，确认连接持久化和导航行为没有回归。
