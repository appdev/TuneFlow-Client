# TuneFlow 桌面播放器极简一体化设计

日期：2026-08-13

状态：已确认

## 目标

优化桌面全屏播放器，使整个窗口成为一张连续、安静的沉浸画布，消除顶部、
内容和底部播放区之间的拼装感。播放器只保留完成当前播放任务所必需的内容，
播放核心始终位于窗口视觉中心，音质与队列作为临时操作出现。

本规格延续项目 `design.md` 中的 Mist Sea、Split Studio、封面衍生背景、
语义令牌和跨平台规则，不引入新的页面主题。

## 范围

本规格包含：

- 桌面全屏播放器的整体结构与视觉收敛。
- 桌面进度条和核心播放控制的布局及交互。
- 桌面音质选择菜单。
- 桌面播放队列浮层与长队列滚动。
- 移动端进度条命中区域与长队列行为的对应调整。
- 对应响应式、无障碍、组件与视觉测试。

本规格不包含：

- 修改搜索、榜单、歌单详情等非播放器页面。
- 增加随机、循环、收藏、下载或评论等未确认功能。
- 唱片机、旋转唱片或其他装饰性播放器皮肤。
- 重构播放数据源、队列持久化或音频服务协议。
- 修改已经确认的移动端 A 型控制区和 C 型队列的信息架构。

## 设计原则

1. 整个播放器窗口只是一张画布，不是顶部栏、内容面板和底栏的组合。
2. 音乐内容是视觉前景；界面控件只在需要操作时获得边界。
3. 歌曲信息只出现一次，避免封面区与底部控制区重复展示。
4. 进度、上一首、播放／暂停、下一首是播放核心，必须严格以窗口中心为锚点。
5. 音质和队列属于次要操作，不得参与核心控制区的宽度计算，也不得把核心控件挤偏。
6. 队列无论多长都只在临时容器内部滚动，不改变播放器主布局。

## 桌面主界面

### 连续画布

当前封面生成的背景覆盖播放器整个客户区，包括窗口顶部内容区和底部控制区域。
顶部和底部不再铺设独立的高不透明背景，也不使用横向分割线。

区域关系依靠留白、位置和文本层级建立。允许局部按钮使用 `glassClear`，但不得用
玻璃表面包裹整条顶部栏或整条底部控制区。

### 保留内容

桌面播放器只保留：

- 返回按钮。
- 当前封面。
- 歌曲名、歌手和专辑；专辑缺失时不保留尾部分隔符或空位。
- 歌词阅读区；有翻译时随当前歌词显示。
- 当前时间、进度、总时长。
- 上一首、播放／暂停、下一首。
- 音质选择入口。
- 播放队列入口。

### 删除内容

桌面播放器删除：

- 顶部“正在播放 · 音流”等状态标题。
- 播放器内搜索入口。
- 与当前任务无关的更多菜单或装饰性图标。
- 底部重复的封面、歌曲名和歌手。
- 整条顶部或底部面板填充。
- 区域之间的横向分割线。
- 无歌词状态中的大型装饰图标。
- 尚未接入业务的收藏、评论、皮肤、分享或类似假操作。

### 主体布局

桌面宽度下继续使用 Split Studio：

- 左侧为方形封面和唯一一组歌曲信息。
- 右侧为歌词阅读区。
- 两侧形成稳定但不机械对称的约 42／58 比例。
- 封面尺寸随窗口约束，在大窗口中不得无限放大。
- 歌词与封面在视觉上共享同一垂直中心。

无歌词时，右侧保留与歌词相同的阅读区域，只显示低强调文案“歌词暂不可用”和
一个明确的“重试”操作。提示不得占据整个画面中心，也不得放大成主视觉。

## 桌面播放控制

### 中心锚定

进度条和三枚核心播放按钮构成一个独立的中心控制组。该组以播放器可用窗口的
水平 50% 为锚点，而不是在“左侧歌曲信息 + 中间控制 + 右侧操作”的普通 Row 中
平均分配空间。

音质和队列入口独立定位在控制区右侧。它们出现、隐藏、改变宽度或展开浮层时，
不得改变进度条、播放按钮或上一首／下一首的位置。

### 进度条

- 可见轨道高度为 4 px。
- 拖动点静止直径为 12 px；悬停或拖动时可提高至 14 px，但不得造成布局变化。
- 实际鼠标和触控命中高度不小于 28 px。
- 点击轨道任意位置可跳转，按住并移动可连续拖动。
- 时间文本保持在轨道两侧，使用数据字体和等宽数字。
- 禁用、加载和未知总时长状态不改变整体几何。

### 核心按钮

- 上一首、播放／暂停、下一首保持居中。
- 播放／暂停是唯一高强调圆形按钮。
- 上一首或下一首不可用时保留原位，通过禁用状态表达，避免中心组跳动。
- 所有按钮的命中区域不小于 44 px。

## 音质选择

点击“无损”或当前音质入口，在入口按钮上方展开一个小型临时菜单。

菜单只展示当前服务支持并已接入的音质，例如：

- 标准 `128k`。
- 高品质 `320k`。
- 无损 `flac`。

当前选项同时使用强调色和勾选图标标记，不能只依赖颜色。选择后菜单关闭并更新
当前音质；失败时保留原音质，在菜单附近显示局部错误和重试，不弹成功 Toast。

菜单不得改变主界面尺寸，也不得推动核心播放控制。

## 桌面播放队列

### 展示方式

点击“队列”后，在播放器右下方、队列入口上方展开一个临时玻璃浮层。浮层属于
当前播放器窗口，不增加固定侧栏，也不压缩封面、歌词或中心控制组。

浮层包含：

- 固定标题“播放队列”和队列数量。
- 固定“清空”操作。
- 可独立滚动的歌曲列表。
- 当前播放标识。
- 每行的歌曲名、歌手和单曲移除按钮。

### 长队列

- 浮层最大高度不超过播放器可用高度的约 68%，并受顶部安全留白约束。
- 标题、数量和清空操作固定；只有歌曲列表滚动。
- 支持鼠标滚轮、触控板和键盘滚动。
- 滚动条使用低强调窄样式；没有滚动时不抢占视觉注意力。
- 当前歌曲切换时，当前标识实时更新；不强制把用户正在查看的位置跳回顶部。
- 初次打开时，若当前歌曲不在可视范围，自动将其滚动到舒适的可视位置。
- 歌曲数量很大时使用惰性列表构建，不一次渲染全部行。

### 行为

- 点击非当前歌曲立即调用现有 `playIndex(index)`。
- 点击当前歌曲不重启播放。
- 点击移除按钮只移除对应歌曲，不触发行点击。
- 清空队列继续使用已确认的危险操作确认流程。
- 切歌、移除或清空失败时错误留在浮层内，并提供重试。
- 点击浮层外部、再次点击队列按钮、按 Escape 或系统返回关闭浮层，播放不中断。

## 移动端对应调整

移动端保持已经确认的 A 型连续控制区和 C 型可拖动队列 Sheet，不复制桌面右下浮层。

### 移动进度条

- 可见轨道和拖动点采用与桌面一致的 4 px／12 px 规则。
- 实际触控命中高度不小于 44 px；视觉轨道仍保持克制。
- 拖动过程中不触发横向封面／歌词 PageView 切换。
- 文字放大时优先保持进度条和主控制可达，时间文本不得挤压轨道至不可操作。

### 移动长队列

- Sheet 初始高度保持可用视口的约 64%。
- 可在 48%–90% 之间拖动。
- Sheet 高度达到上限后，手势转交给内部列表滚动。
- 标题、数量、清空和拖动把手保持可见；歌曲列表独立滚动。
- 初次打开时将当前歌曲滚动到可视位置。
- 大队列使用惰性 Sliver 列表，不一次构建所有行。
- Sheet 尊重底部安全区、系统返回、键盘焦点和屏幕阅读器顺序。

## 状态与无障碍

- 返回、播放、上一首、下一首、音质和队列均提供中文语义标签与 Tooltip。
- 桌面支持 Tab 焦点、Enter／Space 激活和 Escape 关闭临时浮层。
- 焦点环立即出现，不做淡入动画，且对比度至少为 3:1。
- 当前播放歌曲使用图标、`selected` 语义和文本状态共同表达。
- 音质当前项使用勾选、语义选中状态和强调色共同表达。
- 加载状态不得改变按钮尺寸或播放控制中心位置。
- 减少动态时，菜单和浮层只使用不超过 150 ms 的透明度变化。

## 架构边界

- `PlayerScreen` 继续负责桌面与移动布局分流，不改变播放器路由。
- 桌面主体、中心控制组、音质菜单和队列浮层应拆成边界清晰的私有或独立组件，
  避免继续扩大单个布局方法。
- `PlayerController` 继续作为播放、音质和队列命令的唯一入口；UI 不直接修改状态。
- 桌面与移动队列共享行为和行语义，但拥有各自适合平台的容器。
- 现有 `showAppSheet` 保留给移动端队列；桌面队列使用受窗口约束的非模态浮层。

## 响应式行为

- 1440×960 和 1024×768 使用桌面一体化 Split Studio。
- 768 px 窗口继续沿用项目现有的移动布局判定，不强行塞入桌面双栏。
- 桌面窗口高度不足时，优先缩小封面和主体间距；进度与播放控制必须始终可见。
- 浮层不得超出播放器窗口，也不得遮挡中心播放按钮。
- 320、360、375、390、414 和 768 px 移动／窄窗路径不得产生水平溢出。

## 验收标准

### 视觉

- 桌面顶部、主体和底部使用同一张连续背景。
- 不存在顶部或底部整条独立面板。
- 不存在区域横向分割线。
- 歌曲信息只出现一次。
- 播放控制在音质菜单或队列浮层打开前后均保持水平居中。
- 无歌词状态安静、局部，不成为画面主焦点。

### 交互

- 进度条可点击、可拖动，命中区域满足桌面 28 px、移动 44 px。
- 音质按钮打开小型菜单，选择后更新并关闭。
- 队列按钮打开桌面右下浮层或移动端 Sheet。
- 86 首及更长队列只在列表内部滚动，不改变播放器尺寸。
- 队列初次打开能够看到当前歌曲。
- 点击行、点击移除、清空和失败重试保持既有行为。

### 验证

- Widget 测试覆盖桌面控制中心位置不受右侧操作影响。
- Widget 测试覆盖桌面音质菜单打开、选择、失败和关闭。
- Widget 测试覆盖桌面长队列滚动、当前项定位、行点击与移除隔离。
- Widget 测试覆盖移动端进度拖动不切换 PageView。
- Widget 测试覆盖移动长队列拖动与内部滚动边界。
- 更新桌面播放器 1440×960、1024×768 以及移动播放器视觉基准。
- 运行相关播放器测试、完整视觉测试、`flutter analyze` 和 macOS debug build。
- 使用真实 Service 地址在 macOS 宽窗和窄窗下完成交互验收。

## 实施风险

- 中心控制若继续放在普通三段 Row 中，会受到右侧菜单宽度影响；实现必须使用独立中心约束。
- 桌面浮层和主播放器都响应滚轮时可能产生滚动穿透；浮层列表需要截获边界内滚动。
- 移动进度拖动与 PageView 横向手势可能竞争；必须用 Widget 测试验证手势归属。
- 自动定位当前歌曲不能在每次播放状态更新时反复触发，否则会打断用户浏览队列。
- 真实封面亮度差异较大，连续背景仍必须通过主题 veil 保持文字和控件对比度。
