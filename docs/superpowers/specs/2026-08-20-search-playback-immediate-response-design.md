# 搜索播放即时响应设计

## 背景

搜索结果缺少内嵌封面时，当前点击处理会先等待封面接口，再把歌曲交给
`PlayerController`。封面请求的延迟因此直接表现为迷你播放器没有响应，用户也看不到
播放加载状态。

## 目标

- 点击搜索结果后立即把所选歌曲设为当前曲目并开始播放加载。
- 封面尚未取得时沿用现有默认占位图设计。
- 封面加载不得阻塞播放，也不得让旧请求覆盖用户后来选择的歌曲。
- 保持搜索结果“仅播放所选歌曲”的现有队列语义。

## 非目标

- 不修改播放器解析音频、播放队列或默认封面组件。
- 不重构专辑、在线歌单等其他入口的封面加载流程。
- 不新增超时、重试或用户提示策略。

## 设计

搜索页收到歌曲点击后，首先调用 `PlayerController.play(track)`。播放器现有实现会同步
写入队列和当前索引、设置加载状态并通知监听者，因此迷你播放器会立刻显示所选歌曲；
缺少封面 URL 时，`AppArtwork` 自动使用现有占位图。

随后，搜索页在后台请求歌曲封面。请求成功且 URL 有效时，通过
`PlayerController.updateTrackArtwork(track, picture)` 更新播放器队列中的匹配歌曲。
该方法按来源和歌曲 ID 匹配；如果用户已播放另一首搜索结果，旧歌曲已不在单曲队列中，
旧请求不会覆盖新的当前曲目。请求失败时保持占位图，不中断或回滚播放。

## 状态顺序

1. 用户点击搜索结果。
2. 播放器立即发布所选歌曲和加载状态。
3. 迷你播放器以占位图显示所选歌曲。
4. 音频解析与封面请求相互独立地异步执行。
5. 封面成功返回时只更新匹配歌曲的 artwork；失败时不改变播放状态。

## 验证

在搜索页面 widget 测试中挂起封面接口，并验证：

- 封面请求尚未完成时，`player.state.current` 已经是点击的歌曲。
- 当前队列仍只包含该歌曲，并处于播放加载流程。
- 封面完成后，当前歌曲的 `pic` 更新为返回 URL。

保留并运行搜索页面现有测试，确认内嵌封面和“仅播放所选歌曲”的行为不回归。
