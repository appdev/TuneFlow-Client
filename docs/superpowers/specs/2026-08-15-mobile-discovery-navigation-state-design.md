# 移动端发现入口、集合详情与 Tab 状态设计

## 目标

调整 TuneFlow Flutter 客户端的移动端一级导航：把“歌单广场”和“排行榜”合并为可点击标签、可左右滑动切换的“发现”页，将“下载”移入“更多”。修复搜索结果中的歌单和专辑卡片不可点击，并让同一 Service 连接期间的一级 Tab 保留已加载数据、滚动位置、搜索条件和各自导航栈。

## 已确认的产品行为

- 移动端底栏依次为：首页、搜索、发现、我的音乐、更多。
- “发现”默认显示“歌单广场”，顶部可切换“歌单广场 / 排行榜”，内容支持左右滑动。
- “下载”不再占用移动端底栏，入口移入“更多”。
- 桌面端继续保留独立的“歌单广场”“排行榜”“下载管理”等导航项，不合并页面。
- 搜索结果中的歌单进入现有在线歌单详情；专辑进入完整专辑详情并展示歌曲列表。
- 同一 Service 连接期间切换一级 Tab 不重新加载；返回时保留原标签、滚动位置、搜索条件和子页面导航栈。
- 只有用户主动刷新、相关领域事件使数据失效，或断开/更换 Service 时才重新读取。
- 本次解决的是运行期状态生命周期，不增加磁盘数据缓存。

## 现状与根因

### 移动端入口

`AppShell` 当前把“下载”列为移动端一级目的地，而 `/square` 和 `/charts` 在移动端都映射到“更多”。`MoreScreen` 同时展示歌单广场和排行榜入口。这与目标信息架构相反。

### 重复加载

当前使用单个 `ShellRoute`。一级导航通过 `context.push(...)` 创建新的路由页面；各路由 builder 同时创建新的页面 Controller，页面在销毁时又 dispose Controller。首页、我的音乐、下载等页面会在 `initState` 中发现空状态并调用 `refresh()`，因此重新进入 Tab 会产生新的网络请求。

这不是磁盘缓存缺失，而是路由页面和状态对象的所有权过短。

### 集合卡片不可点击

搜索结果中的 `_CollectionCard` 只绘制封面和文本，没有点击回调、交互语义或导航接线。在线歌单详情能力已经存在；客户端目前只有专辑搜索调用，没有专辑详情 Repository 方法、模型、Controller 或页面。

## 方案比较

### 方案 A：持久化 Stateful Shell（采用）

使用 `StatefulShellRoute.indexedStack` 为一级目的地提供独立 Navigator 和持久页面实例。切换目的地不销毁页面，因此能同时保留 Controller 数据、Widget 状态、滚动位置、输入框和子路由栈。相关领域事件继续使用现有失效版本定向重建。

该方案需要调整路由和 Shell 接口，但状态所有权清晰，直接满足完整验收条件。

### 方案 B：只把 Controller 提升到 Riverpod

长生命周期 Provider 可以避免多数数据重复请求，但页面仍会销毁。滚动位置、搜索框、选中标签及页面内临时状态需要分别恢复，容易出现状态来源分裂。

### 方案 C：页面级缓存与 PageStorage

为每个页面分别缓存响应、ScrollController 和筛选条件，初期路由改动较小，但重复实现多、失效边界不一致，后续维护风险最高。

## 路由与导航架构

### Stateful Shell

一级页面改由 `StatefulShellRoute.indexedStack` 承载。每个分支拥有稳定 Navigator key，并保留其根页面与分支内详情页：

- 首页；
- 搜索；
- 发现；
- 我的音乐；
- 更多；
- 桌面端仍需直接访问的歌单广场、排行榜、下载管理、设置和音源管理分支。

`AppShell` 接收 `StatefulNavigationShell`，内容区直接展示 navigation shell。点击一级导航调用 `goBranch`，再次点击当前分支时返回该分支根页面。普通详情操作继续在所属分支内 push，保证返回时恢复列表页面。

移动端只渲染五个目标；桌面端继续渲染原有目标。路径的选中态映射同步更新：`/discover` 属于“发现”，`/downloads`、`/settings` 和 `/sources` 在移动端属于“更多”。

### 发现页

新增移动端发现容器，使用一个稳定的 `TabController` 和 `TabBarView`：

1. 歌单广场；
2. 排行榜。

标签点击与横向手势共享同一选中状态。两个子页在首次访问后保持存活，切换时不重新创建各自 Controller。现有歌单广场和排行榜内容提取为可嵌入内容组件；桌面端独立页面继续复用同一内容，不复制业务逻辑。

发现页默认索引为歌单广场。返回该 Tab 时保留当前索引、筛选条件和两侧滚动位置。

### 更多页

移除“歌单广场”和“排行榜”条目，新增“下载管理”条目。音源管理、设置、断开连接和 Service 状态保持现有行为。

## 搜索集合详情

### 可点击卡片

搜索集合网格接收统一的 `onOpenCollection(CatalogCollection)` 回调。卡片使用 `InkWell` 或项目已有可点击卡片模式，提供：

- 完整卡片点击区域；
- 按压反馈；
- button 语义和包含集合名称的可访问标签；
- 稳定测试 key。

回调按 `CatalogSearchKind` 分发：

- `playlist`：进入现有 `/square/:source/:playlistId` 在线歌单详情；
- `album`：进入新的专辑详情路由；
- 非法或未知类型：不导航，并显示明确错误反馈。

移动与桌面搜索结果使用相同导航规则。

### 专辑详情

新增专辑详情 Repository 契约、响应模型、Controller 和页面。页面展示搜索结果提供的初始封面和元数据，并异步读取权威歌曲列表；功能包括：

- 专辑封面、名称、歌手、描述和歌曲数量；
- 播放全部；
- 从任意歌曲开始播放完整专辑队列；
- 复用现有歌曲操作，包括添加到我的歌单和下载；
- 加载、空、分页、失败及保留旧数据的 stale 状态。

客户端拟使用 `POST /api/v1/catalog/albums/detail`，请求至少包含 `source`、`albumId` 和 `page`。响应应提供专辑元数据、歌曲列表、分页及 `hasMore`。这是本功能新增的 Service 契约要求，不是当前客户端已经具备的接口。实施时必须以实际 Service 契约为准同步字段和能力声明，不得用同名歌曲搜索结果模拟专辑详情。

若连接的 Service 或音源不支持专辑详情，点击仍进入详情页，但页面显示“当前音源不支持专辑详情”，保留搜索结果的专辑元数据并允许返回，不产生无效歌曲列表。

## 状态所有权与失效

- 一级页面的 Controller 由持久分支页面持有，不再随 Tab 切换销毁。
- 页面只在 Controller 为空且从未加载时执行首次加载。
- 首页、我的音乐、下载、本地曲库和歌单详情继续响应现有 `EventInvalidation` 版本；相关版本变化允许定向重建或调用 invalidate/refresh。
- 搜索词、来源、结果分页和图片请求缓存随搜索分支保留。
- 发现页的歌单分类、排行榜音源、选中榜单及已加载内容随发现分支保留。
- 用户主动刷新只影响当前功能域，不清空其他 Tab。
- 断开或更换 Service 时销毁整个 Stateful Shell 及其 Controller，避免跨 Service 串数据。
- 不把 Service 响应写入本地数据库或偏好设置；应用进程结束后无需恢复这些页面数据。

## 错误处理

- 首次加载失败：显示当前页面的明确错误状态和重试操作。
- 刷新失败且已有内容：保留内容并标记 stale，不清空列表或跳回根页面。
- 专辑详情不受 Service/音源支持：显示能力不支持提示，不把它表述为网络错误。
- 专辑详情网络或解析失败：使用统一的用户友好错误映射并提供重试。
- 卡片连续点击：由路由和 Controller 的 pending 状态避免重复详情请求。
- Service 切换：旧页面和未完成结果不得写入新连接状态。

## 测试与验收

### 导航测试

- 移动底栏显示：首页、搜索、发现、我的音乐、更多，且不显示下载。
- “更多”包含下载管理，不再包含歌单广场和排行榜。
- 桌面导航结构保持不变。
- 各一级分支拥有独立导航栈；从详情返回恢复所属列表。
- 切换一级 Tab 后返回，不重复创建页面或发起首次请求。

### 发现页测试

- 默认显示歌单广场。
- 点击排行榜标签可以切换。
- 左右滑动可以双向切换，标签状态同步。
- 离开发现 Tab 再返回时保留标签、筛选和滚动位置。
- 两个子页的加载错误互不覆盖。

### 集合详情测试

- 搜索歌单卡片具有点击回调并进入在线歌单详情。
- 搜索专辑卡片具有点击回调并进入专辑详情。
- 专辑详情解析分页、累积歌曲，并从正确索引播放完整队列。
- 专辑歌曲可使用现有添加歌单和下载操作。
- Service 不支持专辑详情时显示能力提示。
- 无效响应显示解析错误，已有数据刷新失败时保留旧数据。

### 状态测试

- 首页与我的音乐往返时各自 Repository 请求计数不增加。
- 搜索页往返后保留查询词、来源、结果视图和滚动位置。
- 相关 invalidation 事件只刷新目标域。
- 重新连接 Service 后旧状态全部清空并加载新连接数据。

### 验证

运行相关 Controller、Repository、Widget 和路由测试，再运行覆盖修改文件的 `flutter analyze`。执行移动尺寸下的布局测试，检查窄屏无溢出。若 Android 设备可用，再验证底栏切换、发现页横向手势、返回栈和网络请求次数；当前调查时 `adb devices` 没有发现设备，因此真机验证不是本地自动验证的前置条件，但必须在交付中列为未验证项。

## 范围外与风险

- 不增加磁盘数据缓存、离线搜索结果或跨进程页面恢复。
- 不改变 Service 数据的权威来源，也不从其他搜索结果推断专辑歌曲。
- 不修改桌面端的信息架构。
- 专辑详情的端到端可用性依赖 Service 提供并声明相应详情能力；仅修改客户端不能使缺少该契约的旧 Service 返回专辑歌曲。
- 当前工作树包含大量用户未提交修改，实施必须用小范围补丁保留现有改动，尤其避免覆盖路由、播放器、歌单、本地曲库和视觉测试中的在途工作。
