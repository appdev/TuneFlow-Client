# TuneFlow 移动播放器控制区与播放队列设计

日期：2026-08-13

状态：已确认

## 目标

重新组织移动端全屏播放器的下半区，使歌曲信息、次要操作、进度和
核心播放控制形成连续、稳定的阅读顺序；同时把播放队列改为独立的
半屏 Sheet，并补齐移除单曲与清空队列能力。

设计借鉴用户提供的 QQ 音乐截图中的功能层级，但不复制其视觉皮肤、
唱片机装饰、会员内容、广告、品牌图标或专属交互。成品继续遵守项目
`design.md` 中的 Mist Sea、Liquid Glass、语义令牌与跨平台规则。

## 范围

本规格包含：

- 移动端全屏播放器的底部播放控制区。
- 移动端播放队列半屏 Sheet。
- 队列选择、移除单曲与清空队列行为。
- 队列变化涉及当前歌曲时的播放状态迁移。
- 对应控制器、音频端口、组件、无障碍与测试调整。

本规格不包含：

- 桌面播放器结构调整。
- 随机播放、循环模式或播放顺序持久化。
- 拖拽排序、播放历史或“已播歌曲”分页。
- 新增收藏、下载等尚未接入播放器控制器的业务能力。
- QQ 音乐的唱片机视觉、VIP 标记、会员入口或广告。
- 服务器连接门禁；它是独立功能，应使用另一份规格实施。

## 已确认的设计方向

### 主播放页：A 连续控制层

移动端主播放页保留当前封面模糊背景，并继续支持封面与歌词之间的
横向切换。现有队列不再作为第三个横向页面，避免与队列按钮形成重复
入口。

页面从上到下分为：

1. 顶部工具栏：返回、当前播放提示、更多操作。
2. 主内容区：封面页或歌词页。
3. 连续底部控制层：歌曲信息、次要操作、进度和主播放控制。

底部控制层使用一个完整的 `glassClear` 功能表面，不拆成多块悬浮卡片，
也不嵌套玻璃。其内部顺序固定为：

1. 歌曲名、歌手和音质；歌曲名最多一行，歌手与音质为次级信息。
2. 已接入且可用的次要操作。未接入业务能力的图标不得作为假按钮出现。
3. 可拖动进度条，以及当前位置和总时长。
4. 上一首、播放／暂停、下一首、播放队列。

播放／暂停是唯一突出的圆形主按钮。其他按钮保持等宽、低强调；禁用的
上一首或下一首仍保留位置，避免控制区在边界状态跳动。所有触控目标不小于
44 px。

### 播放列表：C 半屏 Sheet

点击控制区的队列按钮后，从底部打开独立的播放队列 Sheet。Sheet 初始占用
可用视口高度的 64%，允许在 48%–90% 之间拖动；达到当前高度上限后只滚动
列表。它不得遮挡系统安全区，也不得嵌套卡片。

Sheet 包含：

- 拖动把手与标题“播放队列”。
- 队列歌曲数量。
- 右侧“清空”文本操作。
- 可滚动歌曲列表。

每个队列行只显示：

- 歌曲名。
- 歌手。
- 当前播放标识。
- 单曲移除按钮。

当前歌曲使用语义强调色、播放波形图标与 `selected` 语义共同标记，不能只依赖
颜色。点击歌曲主体立即切换到该歌曲；点击移除按钮只执行移除，不触发行点击。

## 状态与数据流

### 打开与关闭

1. 用户点击主播放控制区的队列按钮。
2. `PlayerScreen` 打开队列 Sheet，并监听同一个 `PlayerController`。
3. 队列变化直接刷新 Sheet；不创建列表副本或第二套队列状态。
4. 用户下滑、点击遮罩或使用系统返回关闭 Sheet，播放不中断。

### 选择歌曲

- 点击非当前歌曲调用现有 `playIndex(index)`。
- 切换开始后当前行立即进入加载状态，解析或播放失败时保留队列并显示局部错误。
- 点击当前歌曲不重启播放，也不关闭 Sheet。

### 移除非当前歌曲

- 删除当前索引之前的歌曲时，当前歌曲保持不变，`currentIndex` 向前修正一位。
- 删除当前索引之后的歌曲时，当前歌曲与 `currentIndex` 不变。
- 操作采用静默成功；列表立即收拢，不弹成功 Toast。

### 移除当前歌曲

- 当前歌曲后面还有歌曲：移除后立即播放原来的下一首。
- 当前歌曲位于队尾且前面还有歌曲：移除后立即播放新的队尾歌曲。
- 队列只有当前歌曲：停止音频，清空播放器状态并关闭 Sheet。
- 切换下一首失败时保留删除后的队列和失败歌曲元数据，显示可重试错误，不回滚已确认的删除。

### 清空队列

- “清空”是影响整条队列的操作，点击后显示轻量确认对话框，明确说明会停止当前播放。
- 确认后停止音频、清空播放器状态并关闭 Sheet。
- 取消后不改变队列、位置或播放状态。
- 队列为空时“清空”禁用。

## 架构边界

### `PlayerController`

新增明确的队列命令，而不是让 UI 直接修改 `PlayerState.queue`：

- `removeAt(int index)`：执行索引修正与当前歌曲迁移。
- `clearQueue()`：停止音频并恢复空播放器状态。

命令负责保持队列、当前索引、播放元数据与音频输出的一致性。UI 只传入用户意图。

### `AudioPort`

现有端口缺少“停止但仍保持端口可继续使用”的能力。新增 `stopPlayback()`，
其语义是停止当前音频并发布 idle 快照，但不释放播放器、事件流或音频服务。
`ServiceAudioHandler.stop()` 仍保留为生命周期销毁入口，不能被队列清空复用。

所有 `AudioPort` 实现与测试替身必须实现新增能力。

### 播放器组件

- `PlayerScreen` 保留桌面路径不变，仅重组 `_MobilePlayer`。
- 主播放控制区提取为边界清晰的移动组件，消费 `PlayerState` 与控制回调。
- `QueuePanel` 增加可选的移除和清空能力，或新增移动专用 Queue Sheet 内容组件；
  桌面调用者不应被迫获得移动端管理操作。
- Sheet 仍通过项目现有 `showAppSheet` 路径打开，以保留跨平台返回、焦点与遮罩行为。

## 视觉规则

- 使用 `design.md` 的 Mist Sea 语义颜色、字体、4 px 间距尺度和圆角。
- 主控制层使用 `glassClear`；队列 Sheet 使用 `glassSheet`。
- 背景继续由当前封面产生模糊层，控制层不从封面抽取任意强调色。
- 主控制层只使用一个玻璃表面；Sheet 列表行保持稳定、近乎不透明，避免逐行玻璃。
- 动画只使用位移与透明度；标准 Sheet 过渡不超过 280 ms，减少动态时改为不超过
  150 ms 的透明度变化。
- 正文对比度不低于 4.5:1；控制边界、图标与大文本不低于 3:1。
- 系统文字放大时，歌曲名和歌手允许省略，播放控制不换行、不溢出。

## 交互状态

按钮与队列行需覆盖：默认、悬停（桌面窄窗测试）、键盘焦点、按下、禁用、加载、
错误和成功后的稳定状态。

- 焦点环立即出现且不动画。
- 播放加载时主播放按钮显示稳定的加载反馈，但不改变按钮尺寸。
- 队列切歌失败在 Sheet 内显示局部错误与重试，不关闭 Sheet。
- 清空确认使用明确的危险操作文案；取消是默认安全路径。
- 所有图标按钮提供中文语义标签与 Tooltip。

## 响应式行为

- 目标宽度覆盖 320、360、375、390、414 和 768 px。
- 320 px 下优先压缩水平间距和次要文字，不缩小主触控目标。
- 768 px 的窄桌面窗口仍使用移动播放器结构，但保留 macOS 窗口拖动与安全区域。
- 主控制层高度由内容决定，并允许在高度不足时压缩主内容区；播放控制不得被挤出视口。
- 队列 Sheet 的最大高度受安全区约束，列表单独滚动。

## 错误处理

- 队列索引失效时命令安全返回，不抛给 UI。
- 停止音频失败时仍不应伪装为空队列；控制器保留原状态并显示错误。
- 移除当前歌曲后切歌失败时，保留删除后的队列、失败状态与重试入口。
- 歌词加载错误只影响歌词内容，不禁用播放控制或队列。
- Sheet 打开期间播放自然切换时，当前标识随控制器状态更新。

## 验收标准

### 行为

- 移动播放器不再将队列作为第三个横向页面。
- 封面与歌词仍可横向切换。
- 控制区按“歌曲信息 → 次要操作 → 进度 → 主控制”排列。
- 队列按钮打开独立半屏 Sheet。
- 点击队列歌曲立即切歌。
- 可移除任意单曲，并按本规格修正当前索引。
- 移除当前歌曲时按“下一首优先、否则上一首”继续播放。
- 清空队列需要确认，确认后停止播放并退出空播放器。
- 桌面播放器行为与布局不回归。

### 视觉与无障碍

- 360×800、390×844 和窄 macOS 窗口无溢出。
- 控制层与 Sheet 均遵守 Liquid Glass 角色，不出现玻璃嵌套。
- 44 px 触控目标、焦点、禁用、加载、错误与当前播放状态可辨识。
- 屏幕阅读器能区分队列行、当前播放歌曲、移除和清空操作。

### 验证

- `PlayerController` 单元测试覆盖非当前项移除、三种当前项移除分支、清空成功和停止失败。
- Widget 测试覆盖 A 控制区结构、封面／歌词两页、打开和关闭 C Sheet、行点击与移除事件隔离、
  清空确认以及窄宽度无溢出。
- 更新移动播放器高保真 Golden；桌面播放器 Golden 必须保持预期不变。
- 运行相关播放器测试、视觉测试、`flutter analyze` 和 macOS debug build。

## 实施风险

- 当前 `AudioPort` 的 `stop()` 会释放播放器，不能直接用于清空队列；必须新增可复用的停止方法。
- 当前 `QueuePanel` 是共享组件。若直接加入管理按钮，可能影响桌面调用者；实现时应通过可选能力或
  移动专用内容组件隔离。
- 当前 `PlayerView.queue` 已持久存在于状态枚举。移除移动第三页时应保留兼容性或完整检查消费者，
  避免旧状态使 `PageController` 初始页越界。
