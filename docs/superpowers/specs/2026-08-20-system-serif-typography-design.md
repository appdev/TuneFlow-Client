# 系统衬线字体设计

## 目标

解决精简 Noto Serif 子集用于动态歌单、专辑和歌曲标题时产生的逐字字体混排，同时保持大标题的衬线字体风格和精简后的 APK 体积。

## 方案

- `hero`、`display`、`pageTitle`、`mobilePageTitle`、`section` 统一使用系统通用字体族 `serif`。
- Android 根据系统字体配置解析 `serif`；当前 Pixel API 35 环境将简体中文映射到 `NotoSerifCJK-Regular.ttc`。
- 正文、歌曲列表、元数据继续使用平台默认字体，不指定字体族。
- 数字信息继续使用内置的 `IBMPlexMono`。
- 删除 `NotoSerifSC-UI-Subset.ttf` 及其 `pubspec.yaml` 注册；保留字体许可证文件。

## 兼容性

- 不依赖厂商具体字体文件名，只请求 Android 通用 `serif` 字体族。
- 不同 ROM 可能选择不同的系统衬线字体；若设备没有中文衬线字体，系统会统一回退，而不会像不完整子集一样在同一中文标题中混用两套字形。
- 不改变字号、字重、行高、字距、颜色或排版层级。

## 验证

- 排版令牌测试验证所有大标题使用 `serif`，正文不指定字体族。
- 视觉测试移除子集字体加载，确保测试资源不再引用已删除文件。
- 运行静态分析及相关组件、详情页和播放器测试。
- 构建签名、仅 ARM64 的 Release APK，检查不再包含子集字体。
- 在当前 Pixel API 35 ARM64 模拟器安装 APK，确认包可解析并安装。
