# 主导航回到模块首页设计

## 背景

应用使用 `StatefulShellRoute.indexedStack` 保存各主导航分支。当前从歌单详情切换到搜索后，再点击“我的歌单”，路由会恢复歌单分支上次停留的详情页，而不是进入歌单首页。桌面侧边栏和移动端底栏都受此行为影响。

## 目标

- 点击任一主导航入口时，始终进入该模块的根路由。
- 从歌单详情、在线歌单详情或专辑详情等子路由切走后，再点击对应主导航，不恢复子路由。
- 不重建模块首页；保留搜索词、滚动位置和已加载数据等页面内部状态。
- 保持现有前进、后退历史机制不变。
- 桌面侧边栏和移动端底栏采用相同语义。

## 方案

主导航继续通过 `StatefulNavigationShell.goBranch` 切换分支，但每次都将 `initialLocation` 设为 `true`。目标分支因此显示其根路由；`StatefulShellRoute` 的分支容器仍然存在，根页面状态不会因导航点击而被主动重建。

不改用分散的 `context.go` 路径映射，也不重建分支 Navigator。前者会绕开现有分支抽象，后者会丢失页面内部状态。

## 导航语义

1. 用户在某模块的子路由中操作，例如 `/playlists/:id`。
2. 用户点击另一个主导航，例如“搜索”，应用进入 `/search`。
3. 用户再次点击“我的歌单”，应用进入 `/playlists`，不恢复之前的 `/playlists/:id`。
4. 如果用户已经位于当前模块的子路由，重复点击该模块主导航，同样进入模块根路由。
5. 导航历史继续记录最终访问的根路由；使用窗口返回按钮时仍可回到此前访问的栏目。

## 测试

新增或调整 Widget 回归测试，验证：

- 移动端从歌单详情切换到搜索，再点击“我的音乐”，显示歌单首页而非详情页。
- 桌面端侧边栏具有相同行为。
- 跨栏目切换后，搜索首页的输入内容仍然保留，证明没有刷新或重建首页。
- 现有主导航选择状态和前进、后退行为不受影响。

测试遵循先失败、后修复：先让新用例在当前实现下因详情页被恢复而失败，再做最小路由修改使其通过。
