# 播放器下载与收藏快捷动作设计

## 背景与目标

参考用户提供的播放器截图，在不跳转到下载页或歌单页的前提下，为当前歌曲提供直接下载和收藏动作。三个入口共享同一状态与行为：

1. 桌面迷你播放器。
2. 桌面完整播放器。
3. 移动端完整播放器。

移动端迷你播放器保持现有紧凑结构，不增加新按钮。

## 行为边界

### 收藏

- 收藏按钮直接切换 Service 内置 `love` 歌单，不打开歌单选择器或其他页面。
- 展示当前歌曲是否已收藏；切歌后重新查询新歌曲状态。
- 点击时乐观更新界面并暂时禁用重复点击。
- Service 操作失败时恢复原状态，并使用现有应用消息反馈显示“收藏失败”及规范化错误信息。
- 已收藏与未收藏必须通过图形或形态差异表达，不能只依赖颜色；语义标签分别为“取消收藏”和“收藏当前歌曲”。

### 下载

- 下载按钮直接使用播放器当前选择的音质创建当前歌曲的下载任务，不打开下载管理页面。
- 请求期间显示进行中状态并禁用重复点击。
- 成功后显示“已加入下载队列”；失败后恢复可用，并通过现有应用消息反馈显示规范化错误信息。
- 本次不查询或展示持久化的“已下载”状态；按钮表示一次下载动作，而不是下载管理状态入口。

## 架构

新增一个播放器当前歌曲动作控制器，集中管理：

- 当前歌曲身份（`source:id`）。
- 收藏状态、收藏状态加载和收藏请求状态。
- 下载请求状态。
- 切歌时的异步结果隔离，防止旧歌曲请求覆盖新歌曲状态。
- 收藏乐观更新、失败回滚，以及下载成功/失败结果。

控制器复用现有 `LovePlaylistFavorites` 行为与 `DownloadRepository`，不新增收藏数据库、不改变 Service API，也不把歌单和下载职责放入 `PlayerController`。生产路由或运行时依赖创建一个共享实例，并将其注入桌面外壳的 `MiniPlayer` 和播放器路由的 `PlayerScreen`。测试和预览构造保持可注入。

三个界面只负责展示和转发动作，不各自查询仓库。这样从任意入口收藏后，返回迷你播放器或进入完整播放器时都能立即看到一致状态。

## 界面布局

### 桌面迷你播放器

- 在左侧封面和歌曲信息附近加入收藏、下载两个图标动作。
- 中间播放控制和进度保持不变。
- 右侧继续保留音质、歌词和播放队列。
- 宽度不足时优先保证中间播放区和歌曲标题可读，不把新动作移动到右侧任务组。

### 桌面完整播放器

- 在左下歌曲信息对应区域加入收藏、下载动作，形成与参考截图一致的歌曲快捷动作组。
- 中下部播放、进度与上一首/下一首保持现有布局。
- 右下继续保留音质和播放队列，不将新动作放入该组。

### 移动端完整播放器

- 在歌曲信息与播放控制之间加入收藏、下载两个独立动作。
- 每个图标按钮保持至少 44 px 点击目标，并提供中文语义标签和 tooltip。
- 顶部“更多操作”不再重复展示收藏或下载；若没有其他动作，则移除该入口，避免空菜单。

### 图标与视觉状态

- 收藏和下载属于普通界面动作，使用 `shadcn_ui` 导出的 `LucideIcons`。
- 不使用播放、暂停、上一首或下一首的 Lucide 图标；传输控制继续通过 `AppPlaybackIcons`。
- 收藏选中态使用可识别的填充或等价形态差异，并配合播放器语义强调色。
- 下载进行中使用尺寸稳定的进度指示，不导致周围布局跳动。

## 数据流与并发

1. 播放器当前歌曲改变时，动作控制器先重置为该歌曲的未确认状态，再异步查询 `love` 歌单。
2. 查询结果仅在歌曲身份与请求代次仍匹配时生效。
3. 收藏点击先更新本地显示，再调用 `setFavorite`；失败时仅在仍为同一歌曲和同一请求时回滚。
4. 下载点击读取当前 `PlayerState.quality`，与当前歌曲一起提交给 `DownloadRepository.create`。
5. 收藏与下载分别维护请求状态，二者可独立执行；同一动作在请求完成前不能重复提交。

## 错误与可用性

- 未连接 Service 或对应依赖不可用时不呈现可执行的假状态；按钮禁用，并保留明确语义。
- 收藏状态查询失败时保持未确认/未收藏的保守展示，不弹出打断性错误；用户主动点击失败才显示错误反馈。
- 切歌、返回页面或在请求期间打开完整播放器不能让旧请求修改新歌曲状态。
- 所有入口只操作当前歌曲，不改变播放队列、当前播放位置或播放器视图。

## 验证

### 控制器测试

- 初始歌曲查询并展示正确收藏状态。
- 切歌后重新查询，旧查询结果不能覆盖新歌曲。
- 收藏成功、取消收藏成功、失败回滚及防重复提交。
- 下载提交包含当前歌曲和 `PlayerState.quality`，并防止请求中重复提交。

### Widget 测试

- 桌面迷你播放器显示收藏和下载动作，且原音质、歌词、队列及传输控制仍存在。
- 桌面完整播放器在左下动作组显示两个动作，右下控制保持不变。
- 移动端完整播放器显示两个 44 px 动作，顶部不再重复展示它们。
- 三个入口共享收藏状态，并呈现正确语义标签、tooltip、禁用和进行中状态。
- 点击图标不会误触发打开播放器、切歌或其他父级点击行为。

- 运行 `flutter test test/features/player/player_screen_test.dart`。
- 运行 `flutter test test/design/app_components_test.dart`。
- 运行新增的播放器动作控制器测试。
- 运行图标系统约束检查，确认没有引入禁用的 Lucide 传输图标，且直接 Material 图标仍只存在于共享播放图标抽象中。

## 非目标

- 不打开下载管理页或歌单页。
- 不提供任意歌单选择器；本需求的收藏专指内置 `love` 歌单。
- 不修改 Service 下载、歌单 API 或持久化结构。
- 不在移动端迷你播放器增加按钮。
- 不实现下载任务取消、进度管理或已下载状态展示。
