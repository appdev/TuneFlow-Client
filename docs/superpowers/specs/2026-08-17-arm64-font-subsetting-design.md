# ARM64 与字体精简设计

## 目标

将 Android Release APK 限定为 `arm64-v8a`，并移除两套完整中文字体造成的体积负担，在不牺牲动态中文内容可读性的前提下，将 APK 从约 55 MB 降至约 26 MB。

## 已确认方案

- Android 仅支持 `arm64-v8a`，不再包含 ARMv7 或 x86_64 原生库。
- 正文、歌曲名、歌手名、歌单名等动态内容使用平台系统字体，依靠系统中文字体覆盖完整字符集。
- 标题字体保留 Noto Serif SC 的应用界面文字子集，以维持现有标题视觉特征。
- 保留体积约 174 KB 的 IBM Plex Mono，继续用于计数器和表格数字。
- 删除完整 Noto Sans CJK SC 与完整 Noto Serif SC 文件，但保留相应许可证文本。

## 字体子集边界

标题子集从应用源码中的固定界面字符、ASCII、中文标点和全角字符生成。未包含的字符由系统字体回退显示，因此用户生成内容和远端音乐元数据不会显示方框，但极少数字符可能与标题中的内置字形风格不同。

生成命令采用 FontTools `pyftsubset`，产物纳入仓库；构建过程不新增运行时依赖。子集必须保留布局特性、字形名称、字符映射、`.notdef` 和推荐基础字形。

## 代码与测试调整

- 在 `pubspec.yaml` 中移除完整正文中文字体注册，并将标题字体注册指向子集文件。
- `AppTypography` 的正文族改为平台默认字体；标题继续使用精简后的 Noto Serif SC。
- 视觉测试不再加载已删除的完整 Noto Sans，标题测试加载子集字体。
- 字体角色测试改为验证正文使用系统字体、标题使用子集字体、数字使用 IBM Plex Mono。
- Android `defaultConfig` 固定 `arm64-v8a` ABI。

## 验证

- 运行字体与主题相关测试、静态分析和项目规定的图标测试。
- 构建普通 `flutter build apk --release`，确认生成单一 Release APK。
- 检查 APK 中仅存在 `lib/arm64-v8a`，不包含 `armeabi-v7a` 或 `x86_64`。
- 检查 APK 不再包含完整 Noto Sans/Noto Serif 文件，并记录最终大小和 SHA-256。
- 将产物复制到 `/Volumes/备份`，覆盖前先备份现有交付包。

## 非目标

- 不调整应用视觉层级、字号、字重或颜色。
- 不删除依赖包自带的小型字体与图标字体。
- 不配置 Release 签名或更改应用版本号。
