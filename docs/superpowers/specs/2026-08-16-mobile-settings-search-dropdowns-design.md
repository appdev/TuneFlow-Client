# 移动端设置与搜索历史下拉窗设计

## 目标

将移动端设置中的“主题”“语言”“默认音质”从点击后循环切换改为显式下拉选择；将搜索框聚焦时出现的搜索历史从页面内联列表改为锚定搜索框的悬浮下拉窗。两类交互都应让用户先看到全部可选项，并且不改变下方页面布局。

## 范围

- 仅调整移动端交互。桌面端设置现有下拉选择器和桌面端搜索历史浮层保持不变。
- 设置项的数据模型、持久化和控制器接口保持不变。
- 搜索历史的读取、选择、单项删除、清空和搜索行为保持不变。
- “减少透明效果”“边听边存”“歌词翻译”等其他设置不在本次范围内。

## 交互设计

### 移动端设置

“主题”“语言”“默认音质”继续显示为设置卡片中的独立行。点击整行打开与当前行锚定的 `ShadSelect` 下拉窗，并显示所有选项及当前值：

- 主题：跟随系统、浅色、深色。
- 语言：跟随系统、简体中文、English。
- 默认音质：128k、320k、无损。

选择新值后调用现有 `SettingsController` 方法并关闭下拉窗。下拉触发区域维持至少 44 px 的可点击高度，并使用现有主题、边框和排版令牌。

### 移动端搜索历史

搜索框获得焦点、输入为空且存在历史记录时，在搜索框正下方显示悬浮浮层。浮层宽度与搜索框一致，位于页面内容之上，不参与 `Column` 或滚动内容的尺寸计算，因此筛选区和结果区的坐标不会因浮层开关发生变化。

浮层沿用现有历史列表能力：

- 点击历史项：填入关键词、关闭浮层并执行搜索。
- 删除单项：更新列表并保持浮层；删除最后一项后自然消失。
- 清空：清空列表并关闭浮层。
- 点击浮层外部、输入非空内容或完成搜索：关闭浮层。
- 页面滚动时浮层继续锚定搜索框；当搜索框离开可见区域时不应残留在固定屏幕位置。

实现采用锚点与 Overlay 层组合，避免依赖固定顶部偏移，也避免普通 `Stack/Positioned` 在滚动和同级绘制顺序下遮挡异常。

## 组件边界

- `SettingsScreen`：移动端三项偏好改用统一的下拉设置行；桌面端继续复用现有 `_LabeledSelect`。
- `SearchScreen`：维护历史浮层的显示条件和锚点生命周期。
- `SearchHistoryPanel`：继续负责历史内容与动作，可按悬浮样式复用桌面端表面、边框和阴影，不负责改变搜索页布局。
- 控制器与仓库：不修改公开接口。

## 异常与可访问性

- 设置保存失败沿用现有控制器状态和反馈方式，不新增静默回退。
- 下拉窗必须可通过点击外部关闭，并保留框架组件已有的键盘与语义能力。
- 历史项删除按钮保留中文 tooltip；所有行保持移动端触控目标尺寸。

## 验证

- 设置页组件测试验证三项移动端设置能打开完整选项，并且选择后只提交所选值，不再按固定顺序循环。
- 搜索页组件测试记录筛选区在历史浮层打开前后的坐标，确认完全不变。
- 验证历史项选择、单项删除、清空和点击外部关闭行为。
- 运行设置页与搜索页聚焦测试；如涉及共享历史面板，再运行其组件测试。
