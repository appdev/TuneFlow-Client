# 设置入口、关于与检查更新设计

## 背景与目标

TuneFlow 手机端目前可从首页、搜索页和底部 Tab 的“更多”进入设置，入口重复。本次改动收敛手机端设置入口，并在“更多”中补齐项目信息与版本更新能力。

目标：

- 手机端仅保留“更多 → 设置”，移除首页和搜索页的设置按钮。
- 桌面端侧栏的“设置”入口保持不变。
- 在“更多”中新增“关于”和“检查更新”。
- 使用 GitHub 公开 API 检查 TuneFlow Client 的最新正式 Release。

非目标：

- 不实现应用内下载安装、静默更新或后台自动检查。
- 不检查 prerelease、draft 或 Git tags。
- 不改变现有设置项、桌面导航或 Service 连接流程。

## 导航与界面

### 设置入口

手机端首页和搜索页的页头不再显示设置图标，也不再接收仅为该图标服务的回调。底部 Tab 保持五项不变，用户从“更多”页进入设置。桌面端仍从侧栏直接进入设置。

### 更多页

“更多”页保留现有下载管理、音源管理、设置、断开 Service 和连接状态，并新增两个普通列表项：

- 关于：进入独立关于页面。
- 检查更新：留在当前页面执行检查，执行期间禁用重复触发并显示进行中状态。

列表项使用项目现有卡片、字体、间距和 Lucide 图标规则，不引入新的图标库。

### 关于页

关于页展示：

- TuneFlow / 音流名称、应用图标和当前安装版本。
- 项目介绍：TuneFlow 是面向桌面与移动设备的跨平台音乐客户端，连接自托管 TuneFlow Service，把发现、收藏、歌单、下载与播放集中在一致的体验中；客户端本身不提供音乐内容。
- TuneFlow Client 项目地址：`https://github.com/appdev/TuneFlow-Client`。
- TuneFlow Service 项目地址：`https://github.com/appdev/TuneFlow`。
- 简短版权与使用提示：用于个人学习和自托管场景，应遵守所在地法律法规并尊重音乐版权。

项目地址由用户点击后交给系统浏览器打开。打开失败时在应用内提示，不静默失败。

## 更新检查架构

### 数据源

请求 GitHub REST API：

`GET https://api.github.com/repos/appdev/TuneFlow-Client/releases/latest`

请求使用 GitHub 推荐的 JSON Accept 头和明确的 API 版本头，不携带令牌。公开未认证请求受 GitHub 限流约束，限流、离线、超时、非 2xx 响应和无效 JSON 均归为可恢复的检查失败。

只使用响应中的：

- `tag_name`：最新正式版本标签。
- `html_url`：对应 Release 页面。

### 本地版本

本地版本从运行时应用包信息读取，而不是硬编码。项目将 `package_info_plus` 声明为直接依赖，以读取版本名和构建号；使用 `url_launcher` 打开项目与 Release 链接。

### 版本比较

版本比较器接受常见标签形式 `v1.2.3`、`1.2.3` 和 `v1.2.3+4`：

1. 去掉可选的 `v` 前缀。
2. 解析 `major.minor.patch`，依次进行整数比较。
3. 两端都带构建号时再比较构建号；远端未提供构建号且三段版本相同，则视为同一版本。
4. 无法解析的远端标签视为检查失败，不把未知格式误报为新版。

### 交互结果

- 本地已是最新版：显示本地版本和“已是最新版本”。
- 发现新版：显示本地版本与最新版本，并提供“前往下载”按钮打开 API 返回的 Release 页面。
- 检查失败：显示简洁原因与稍后重试建议，不泄露响应正文或内部堆栈。

更新检查仅在用户主动点击时执行，不在启动、进入“更多”或后台自动请求。

## 组件边界与可测试性

- 更新仓库负责 HTTP 请求、状态码检查和响应解析。
- 版本值对象/比较函数负责标签规范化和顺序比较。
- “更多”页负责触发检查、阻止并发点击和展示结果。
- 关于页负责静态项目信息、运行时版本显示和外部链接入口。
- 路由层负责连接“更多”、设置和关于页面，并注入可测试的更新检查依赖。

HTTP Client、包版本读取和外部链接打开能力应保持可替换，Widget 测试不得访问真实网络或启动真实浏览器。

## 验证

- 单元测试覆盖版本相等、远端新/旧、`v` 前缀、构建号和无效标签。
- 仓库测试覆盖成功解析、非成功状态、缺失字段和无效 JSON。
- “更多”页测试覆盖设置/关于入口、检查中防重入、最新版、新版和失败反馈。
- 关于页测试覆盖项目介绍、版本及两个项目地址，并验证点击委托给外部链接能力。
- App Shell 测试确认手机首页、搜索页不再出现设置入口，且“更多 → 设置”仍可达；桌面侧栏设置仍可达。
- 运行相关格式化、静态分析和聚焦 Flutter 测试。

## 风险与约束

- GitHub 未认证 API 存在速率限制，因此不做自动轮询，只响应用户主动操作。
- Release 标签格式必须满足约定；异常格式会提示检查失败。
- 系统可能没有可处理 HTTPS 的浏览器，链接打开失败必须反馈。
- 工作树中已有与播放器、搜索页及其测试相关的用户改动；实现时只在必要位置做局部编辑，保留并避免覆盖这些改动。
